1. Executive Summary
QI-Guard for Stellar is a quantum-enhanced blockchain security intelligence layer delivered as a developer SDK and REST API, purpose-built for the Soroban smart-contract ecosystem.
Stellar's security tooling ecosystem already includes Scout (static analysis), Almanax (LLM-assisted vulnerability detection), Certora Sunbeam (formal verification of WASM bytecode), and the Soroban Security Portal (community audit database). QI-Guard does not compete with these tools. It sits in the gap they leave: continuous on-chain behavioral intelligence, cross-contract risk fusion, and quantum-enhanced anomaly detection — all served through a clean API that any developer can call with an API key in under five minutes.
The product is modeled on QuantumInfra's existing model-serving infrastructure: developers authenticate with an API key, submit data, and receive structured intelligence. There is no quantum knowledge requirement on the user side. The quantum computation happens transparently inside the inference engine.
The MVP is scoped to four capabilities:
•Contract Risk API — analyze a Soroban contract's WASM bytecode and source for vulnerability patterns and architectural risks.
•Behavioral Anomaly API — stream or batch-submit Stellar transaction data and receive anomaly scores per address and interaction cluster.
•Quantum Resilience API — score a contract or wallet against known post-quantum threat vectors.
•Quantum Benchmark — every API response includes a side-by-side classical vs. hybrid performance comparison.
The go-to-market is SCF Build Award funding + QAI Ventures accelerator, targeting 100 developer API integrations within 6 months of launch.

Every existing tool operates at the code level, pre-deployment or at point-in-time audit. None of them:

•Fuse code-level risk with on-chain behavioral evidence into a unified risk score.
•Apply quantum-enhanced feature representations to improve anomaly detection on sparse, high-dimensional blockchain data.
•Provide a quantum resilience score for post-quantum migration readiness.
•Serve all of this through a developer API with API-key authentication — callable from any language, any stack, any CI/CD pipeline.
QI-Guard is the behavioral intelligence and quantum resilience layer. It makes the existing tools better by adding a dimension they cannot provide.

5. Product Modules — MVP Scope
The MVP consists of four modules, each exposed as an independent API endpoint and bundled together in the SDK.
Module 1 — Contract Risk API
Input
•Soroban contract WASM bytecode (binary upload or hex string).
•Optional: Rust source code for deeper analysis.
•Optional: contract address on Stellar Mainnet or Testnet for live context.
Processing
•Bytecode disassembly and structural analysis.
•Vulnerability pattern matching against QI-Guard's Soroban vulnerability taxonomy.
•Architectural risk detection: upgradeability patterns, access control structure, admin privilege exposure.
•Dependency risk: known vulnerable library versions, unsafe external calls.
•Classical ML model produces a base risk score.
•Hybrid quantum-classical model produces an enhanced risk score.
•Benchmark comparison is logged and included in the response.

Module 2 — Behavioral Anomaly API
Input
•Stellar account address or contract address.
•Optional: transaction batch (array of Stellar transaction objects).
•Optional: time window (default: last 7 days).
Processing
•Ingest transaction history via Horizon API or direct submission.
•Build temporal feature vectors: call frequency, value flows, interaction clusters, invocation patterns.
•Classical baseline: isolation forest + gradient boosting for anomaly scoring.
•Hybrid model: variational quantum circuit layer for feature transformation before classical classification head.
•Benchmark both architectures; report delta.
Output — Behavioral Risk Profile

Module 3 — Quantum Resilience API
Input
•Stellar account address OR Soroban contract address OR WASM bytecode.
•Optional: list of cryptographic libraries used.
Processing
•Detect signature algorithm in use (Ed25519, Secp256k1, Secp256r1/passkeys).
•Identify exposed public key surfaces.
•Scan contract for cryptographic primitive dependencies.
•Assess migration readiness against NIST PQC standards (CRYSTALS-Dilithium, FALCON, SPHINCS+).
•Score against known quantum attack vectors — Grover, Shor applicability.

Module 4 — Quantum Benchmark
Every API call automatically runs both classical and hybrid inference and records the comparison. The benchmark is returned inline in the response AND stored in the developer's dashboard.
Key metrics tracked per call:
Metric
Description
Precision
True positives / (true positives + false positives)
Recall
True positives / (true positives + false negatives)
F1 Score
Harmonic mean of precision and recall
Anomaly AUROC
Area under ROC curve for anomaly detection tasks
Latency (ms)
End-to-end API response time — classical vs. hybrid
Training cost
Compute tokens consumed per training run
Quantum delta
Hybrid score minus classical score — positive = quantum contributes

This benchmark is QI-Guard's core scientific moat. Over time, the accumulation of benchmark data across thousands of Soroban contracts and addresses creates a proprietary dataset that answers the question no other quantum security product currently answers: where does quantum computation actually improve blockchain intelligence, and by how much?

6. Developer Experience
6.1 Quickstart — 5 minutes to first result
# 1. Install the SDK
npm install @quantuminfra/qi-guard

# 2. Set your API key
export QI_GUARD_API_KEY=qig_live_xxxxxxxxxxxx

# 3. Analyze a contract
npx qi-guard analyze --wasm ./target/wasm32/release/my_contract.wasm

# Response: structured JSON risk report in your terminal
6.2 SDK — JavaScript / TypeScript
import { QIGuard } from '@quantuminfra/qi-guard';

const qg = new QIGuard({ apiKey: process.env.QI_GUARD_API_KEY });

// Contract analysis
const report = await qg.analyzeContract({
  wasm: fs.readFileSync('./contract.wasm'),
  source: fs.readFileSync('./src/lib.rs', 'utf8'),  // optional
});

// Behavioral anomaly
const anomaly = await qg.analyzeAddress({
  address: 'GABC...XYZ',
  window: '7d',
});

// Quantum resilience
const pq = await qg.quantumResilience({ address: 'GABC...XYZ' });

console.log(report.risk_score);  // { classical: 71, hybrid: 78, delta: '+7' }
6.3 SDK — Python
from qi_guard import QIGuard

11. Non-Goals
•QI-Guard will not claim quantum computing automatically makes a model superior — every quantum contribution is measured and reported.
•QI-Guard will not replace Scout, Almanax, Sunbeam, or human auditors — it complements them.
•QI-Guard will not execute exploit transactions against live protocols.
•QI-Guard will not share customer contract data or address history with other customers.
•QI-Guard will not support EVM chains, Solana, or Move ecosystems in the MVP — Stellar/Soroban only.
•QI-Guard will not make autonomous remediation changes — all output is advisory.
